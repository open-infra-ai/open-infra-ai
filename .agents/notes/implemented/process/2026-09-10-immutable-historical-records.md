# Agent Note: 历史记录不可改写，功能性内容随现状同步

Status: implemented

## Problem

审计快照、历史计划、面试材料忠实记录着「当时事实」——旧组织名、旧路径、
当时的数字结论。改名与目录调整若一刀切改写这些文件，会摧毁证据链；若全部
冻结，可执行命令和现场导航路径又会随改名全部失效。需要一条可判定的边界。

## Decision

豁免清单（写在根 `AGENTS.md`）保护**当时事实的叙述**，永不改写：

- `docs/organization-audit/` 审计快照
- 各仓 CHANGELOG 历史条目与 release 链接
- `archive/plans/` 历史计划档案与 `interview/` 面试材料中的旧组织名
- 测试夹具原文（tokenizer fixture 三件套）

同时划定边界：材料中的**功能性内容**（可执行命令、绝对路径、URL、现场要打开
的导航路径）随仓名 / 组织名 / 目录结构变更同步维护，不算改写历史。

## Alternatives considered

- **全部改写到当前名** — 搜索结果最干净；但审计快照引用的「当时事实」被抹掉，
  证据材料无法再自证时间点，与可追溯证据原则冲突。
- **全部冻结** — 零风险；但 2026-09-10 实测显示材料里的绝对路径已指向不存在
  的 `aicl/` 目录，功能性内容冻结 = 文档不可用。

## Consequences

- **收益**：叙述保真 + 命令可用，两者不再互相牺牲。
- **代价**：每次编辑历史材料都要先分类「叙述 / 功能」；判定写进了边界条款，
  仍依赖执行者先读规则。

## Verification

2026-09-10 工作区规范化按此边界执行：interview/ 14 个文件的路径与仓名更新，
7 处 `aicl-lab` 审计叙述逐字保留；记录见根 `changelog/2026-09-10-*.md`。
